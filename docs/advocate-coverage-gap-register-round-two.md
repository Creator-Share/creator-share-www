# Advocate Coverage Gap Register, Round Two

Twenty-two further places where a deliberate, compiling change to production TypeScript passes the entire required suite.

## Read this first

**Every entry is a missing assertion, not a live defect.** The committed code is correct. Each row records that if someone broke that specific behaviour, nothing would fail.

This is a second sweep, over eight subsystems the first one never touched: sponsor accounts, retention workers, audit, storage and media, email workers, administrator lifecycle controls, cancellation and payment-method management, and the sponsor authentication routes. The first sweep's register is closed; see `docs/advocate-coverage-gap-register.md`.

## Method, and the one column that matters

Each proposal was mechanically applied and the suite re-run. All twenty-two survived. That number alone means little, so every file was then probed by appending a throwing statement and running the complete offline lane again:

- **assertion gap** — the suite loads this file, so a surviving mutation is a genuine, specific missing assertion. **Fifteen rows.**
- **no test loads the file** — nothing imports it in any lane, so the finding is about the whole file rather than the line. **Seven rows.**

Two predictions I made before the probe were wrong, which is why the column exists rather than an assumption: the administrator lifecycle and ownership-transfer components _are_ loaded, and the two email runtime modules are _not_.

## Where to start

Two rows have the worst failure modes and should be closed first.

`src/lib/retention/dataRetentionConfig.ts` enforces a 32 character floor on the retention worker secret. Lowering it to 1 is accepted, so a truncated or misconfigured environment variable turns a service-role endpoint that drives every erasure and redaction into something an unauthenticated caller can reach by guessing a one-character bearer. The floor is the only thing standing between a bad env var and an open endpoint.

`src/components/advocates/creatorShareAdmin/AdvocateOwnershipTransfer.tsx` filters ownership-transfer targets on server-computed eligibility. Widening it to "not the current owner" offers suspended and revoked memberships as valid targets for handing over a live portal, and directly contradicts the copy rendered above the form.

Also worth naming: `src/app/api/beneficiaries/[id]/activities/route.ts` already has a test, which asserts _which tenant's_ data it serves. It asserts nothing about _what it projects_, so folding DOCUMENT media into the public images array is undetected. Covering a route's host scoping is not the same as covering its payload.
